## Что НЕ проверено — сделать первым

1. `cd server && cargo clippy --all-targets -- -D warnings && cargo test`
   — Rust писался без компилятора (в чате не было crates.io). Ожидаемы мелкие
   ошибки компиляции/clippy; новые тесты в конце `server/tests/flows.rs`.
2. После `cargo test` сравнить `shared/api-types` (4 файла написаны вручную:
   GroupDto, AssignmentCreateRequest, UserUpdateRequest, AdminResolveSessionRequest),
   затем `npm run sync-types` в admin/ и mobile/.
3. `cd mobile && npm run lint` — линтер не прогнан по `src/app` и `src/screens`
   (tsc --noEmit чистый; admin: tsc -b и eslint чистые).
4. Положить новые `.github/workflows/ci.yml` и `release-android.yml`
   (отправлены пользователю файлами: в чате нельзя писать в `.github/`).
5. Проход на телефоне и по админке.

## Подводные камни

- Сервер не стартует со слабыми `JWT_SECRET`/`QR_SECRET` (`change-me`, < 16 символов).
- Dockerfile: контейнер стартует от root только для `chown /data/*`, затем
  `setpriv` → пользователь `app`.
- Новый package id = новое приложение на телефонах; `mobile/android` пересоздать
  `npx expo prebuild -p android --clean`.
- Автопуш «worker-plus autopush» коммитит каждые 5 минут — промежуточные
  состояния попадают в GitHub.
- `admin/tsconfig.app.tsbuildinfo` изменён прогоном `tsc -b` — можно откатить.
