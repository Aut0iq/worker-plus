## 1. Цель проекта

Приложение для студентов, преподавателей и комендантов, которое учитывает, сколько
часов студенты отработали на общественных работах («отработки»).

Состав продукта:
1. **Сервер** (Rust) — REST API, вся бизнес-логика, учёт времени, журналы, сводки.
2. **Веб-панель администратора** (React) — управление всем.
3. **Мобильное приложение** (Expo / React Native) — для студентов, комендантов и
   преподавателей.

### Исходное ТЗ (дословно по смыслу)
1. Часы отработок выдают (назначают) преподаватели.
2. Отработка начинается только при сканировании студентом QR-кода коменданта.
   Комендант выбирает сложность работ: лёгкие — коэффициент ×1, сложные — ×2.
   Время пишется на сервере секунда в секунду; округление до минут: остаток
   < 30 с отбрасывается, ≥ 30 с — округляется вверх (1ч 43м 31с → 1ч 44м).
3. Все действия логируются на сервере; действия коменданта логируются отдельно,
   с точным временем.
4. Студент может начать отработку, даже если ему её не назначили; такие
   самостоятельно отработанные часы хранятся в профиле.
5. За отработанные часы студент может купить награды в личном кабинете.
6. Каждый месяц создаётся сводка: кто сколько часов отработал.

## 2. Решения, принятые с заказчиком (уточнения к ТЗ)

| Вопрос | Решение |
|---|---|
| Платформа | Мобильное приложение, подключающееся к серверу + веб-панель для админов |
| Стек | Сервер **Rust** (Axum + SQLx + PostgreSQL), мобилка **Expo (React Native, TypeScript)**, админка **React + Vite + TypeScript** |
| Роли | `student`, `teacher`, `komendant`, `admin` |
| Как преподаватель выдаёт часы | В приложении выбирает группу → студента → вводит количество часов (и причину). Часы записываются в профиль студента как **долг** |
| Завершение отработки | Студент прикладывает **фото** + **повторно сканирует QR** того же коменданта |
| Лимит | Если отработка длится **> 4 часов реального времени** (без коэффициента) — не засчитывается, уведомление **админу и коменданту** (и студенту) |
| Подтверждение | **Комендант подтверждает** → часы сразу зачисляются. Фото уходит админу на проверку. Если админ **не зачтёт фото** — часы списываются и записываются в долг |
| Куда идут часы | **Сначала гасят долг**, излишек — на баланс («самостоятельные» часы), который можно тратить в магазине |
| Награды | Магазин наград; награды создаёт **админ**; покупка за баланс → заказ → админ отмечает «выдано» или отменяет (возврат часов) |
| Журнал коменданта | Отдельный журнал всех действий коменданта в приложении: кому начал отработку и во сколько, когда закончил, подтверждения/отклонения, вход, показ QR и т.д. |
| Аккаунты | Создаёт **админ** (вручную или импортом CSV/XLSX), выдаёт логины/пароли |
| Сводка | Автоматически за прошлый месяц; просмотр в админке + выгрузка **Excel (.xlsx)** |
| Уведомления | **Push** (Expo Push) + лента уведомлений в приложении и админке |
| Часовой пояс | **GMT+10** → `Asia/Vladivostok` (настраивается `APP_TIMEZONE`) |
| Деплой | **Docker Compose на VPS** (Postgres + сервер, сервер раздаёт собранную админку) |
| Git | Публичный репозиторий `worker-plus`, сообщения коммитов — `new changes` |

## 4. Бизнес-правила (как реализовано на сервере)

Все суммы — **целые минуты**. Все метки времени — **серверные** (`timestamptz`),
клиентскому времени не доверяем.

### 4.1 Назначение часов (преподаватель / админ)
`POST /api/students/{id}/assignments {minutes, reason}` → запись в `assignments`,
`users.debt_minutes += minutes`, запись в журнал.

### 4.2 QR коменданта
- Комендант выбирает сложность `light` (×1) или `hard` (×2) и открывает QR:
  `POST /api/komendant/qr/open {difficulty}` (пишется в журнал коменданта),
  затем периодически обновляет: `GET /api/komendant/qr?difficulty=` (не логируется).
- Формат: `prila1.<komendant_uuid>.<difficulty>.<window>.<hmac16>`, где
  `window = unix_seconds / 30`, подпись HMAC-SHA256 (`QR_SECRET`), первые 8 байт в hex.
- Валиден в текущем и предыдущем 30-секундном окне (≈ до 60 с) — защита от скриншотов.

### 4.3 Сессия отработки (`work_sessions`)
Статусы: `active` → `pending_confirmation` → `credited` | `komendant_rejected`;
либо `expired`.

1. **Старт** — студент сканирует QR: `POST /api/student/sessions/start {qr}`.
   Проверки: QR валиден, комендант активен, у студента нет другой открытой сессии
   (уникальный индекс в БД). `started_at = now()` сервера, сложность и коэффициент
   берутся из QR. Долг не обязателен (ТЗ п.4).
2. **Финиш** — `POST /api/student/sessions/finish` (multipart: `qr`, `photo`).
   QR должен принадлежать **тому же коменданту**. Фото: jpeg/png/webp/heic ≤ 10 МБ,
   тип проверяется по сигнатуре файла. `ended_at = now()`.
   - `raw_seconds = ended_at − started_at`
   - `rounded_minutes = (raw_seconds + 30) / 60` (целочисленно)
   - `credited_minutes = rounded_minutes × coefficient`
   - если `raw_seconds > 4 ч` → `expired`, ничего не начисляется, уведомления
     админам, коменданту и студенту; иначе → `pending_confirmation`, уведомление коменданту.
3. **Фоновая задача** каждые 60 с: `active` старше 4 ч → `expired` + уведомления.
4. **Подтверждение комендантом** — `POST /api/komendant/sessions/{id}/confirm`
   (только свои сессии): `to_debt = min(debt, credited)`, `to_balance = credited − to_debt`;
   долг уменьшается, баланс растёт; `photo_review = pending` (в очередь админу).
   Либо `.../reject {reason}` → `komendant_rejected`, ничего не начисляется.
5. **Проверка фото админом** — `POST /api/admin/sessions/{id}/photo-review {approved, comment}`.
   Отклонение откатывает зачёт:
   `from_balance = min(balance, applied_to_balance)`; `balance −= from_balance`;
   `debt += applied_to_debt + (applied_to_balance − from_balance)` — то, что уже
   потрачено с баланса, превращается в долг.

Все денежные изменения — в одной транзакции с `SELECT … FOR UPDATE`.

### 4.4 Магазин
Админ ведёт награды (название, описание, цена в минутах, остаток или безлимит,
активность, картинка). Студент покупает **только за баланс**:
`POST /api/rewards/{id}/buy` → заказ `pending`. Админ: `issue` → `issued` или
`cancel` → `cancelled` с возвратом минут и остатка.

### 4.5 Ручная корректировка
`POST /api/admin/users/{id}/adjust {debt_delta, balance_delta, reason}` (итог не
может быть отрицательным).

### 4.6 Месячная сводка
Фоновая задача раз в минуту: если сводки за прошлый месяц нет и (локальный день > 1
или сейчас ≥ 00:05 первого числа) — генерирует. Строки по каждому студенту:
группа, число сессий, сумма округлённых минут, сумма зачтённых минут (только
`credited` и фото не отклонено, `ended_at` в границах локального месяца), назначено
за месяц, снимок долга и баланса. Админ может пересоздать и скачать `.xlsx`.

### 4.7 Журналы
- `audit_log` (+ файл `audit.log.*`): каждое изменяющее действие (входы, в т.ч.
  неудачные, назначения, все этапы сессий, проверка фото, покупки, выдачи/отмены,
  CRUD пользователей/групп/наград, импорт, корректировки, сводки).
- `komendant_log` (+ файл `komendant.log.*`): вход коменданта, открытие QR (со
  сложностью), старт сессии у него (кто, когда), финиш, подтверждение/отклонение,
  истечение. Время с точностью до секунды.

### 4.8 Уведомления
Таблица `notifications` + Expo Push (если `EXPO_PUSH_ENABLED=true`) на токены из
`push_tokens`. Ошибки отправки push логируются и не ломают запрос.

## 7. Запуск на новом ПК

Требования: Git, Rust (rustup, stable), Node.js LTS + npm, PostgreSQL 16 или Docker.

```bash
git clone https://github.com/Aut0iq/worker-plus
cd worker-plus

# База: вариант A — Docker
cp .env.example .env            # задать DB_PASSWORD, JWT_SECRET, QR_SECRET, ADMIN_PASSWORD
docker compose up -d db         # Postgres на localhost:5432
# вариант B — локальный PostgreSQL 16: создать пользователя и БД prila

# Сервер
cp .env.example server/.env     # раскомментировать/добавить DATABASE_URL, PHOTO_DIR, LOG_DIR и т.д.
cd server
cargo run                       # миграции и первый админ создаются при старте; API на :8080
cargo test                      # нужен DATABASE_URL (тесты создают временные БД)
cargo clippy --all-targets -- -D warnings

# Админка
cd ../admin
npm ci
npm run dev                     # http://localhost:5173, /api проксируется на :8080
npm run build && npm run lint

# Мобильное приложение
cd ../mobile
npm ci
npx expo start --lan            # открыть в Expo Go; адрес API — EXPO_PUBLIC_API_URL или поле на экране входа
npm run typecheck && npm run lint && npm test
```

Полный прод-запуск: `docker compose up --build -d` (сервер раздаёт админку).

Тестовые данные есть на тестовом сервере (раздел 5.1a); на новой БД создайте пользователей через админку или импорт.

> Раздел «Environment» в `AGENTS.md` описывает обходные пути старого ПК (WSL без
> сети, `~/prila-env.sh`, `scripts/dev-db.sh`, офлайн-cargo). На нормальной машине
> они не нужны.
