3. В `release-android.yml` добавить шаг: `eas init`/запись projectId перед
   prebuild (или захардкодить в `app.json` и закоммитить).
4. Убедиться, что в `.env` сервера `EXPO_PUSH_ENABLED=true`.
5. Пересобрать APK тегом `v1.0.1`, проверить: вход → токен в
   `POST /api/me/push-token` → push при назначении часов.

**Детали:** `mobile/src/screens/NotificationsScreen.tsx` и регистрация токена

## Баги и потеря данных

1. **Гонка двойного старта сессии → 500 вместо «сессия уже есть».**
   `student.rs` start_session: проверка `open` и `INSERT` — check-then-insert.
   Последовательный дубль уже отдаёт 409 (тест `full_flow_…`, flows.rs:66-75),
   но два действительно параллельных запроса (двойной тап, повтор после
   «нет связи», когда первый запрос дошёл) → второй упирается в уникальный
   индекс `work_sessions_one_open` → sqlx error → `internal` 500.
   **Сделать:** отловить `is_unique_violation` при INSERT → `conflict
   session_exists` (как уже сделано для `login_taken` в create_user).

2. **Ошибки разбора multipart маскируются в «Не передан QR-код».**
   `student.rs` finish_session (и так же import_users, upload_reward_image):
   `while let Ok(Some(field)) = multipart.next_field().await` — ошибка
   `next_field()` (обрыв соединения, тело > 16 МБ DefaultBodyLimit) просто
   завершает цикл → возвращается `missing_qr`/`missing_photo` 400 вместо
   понятной ошибки о размере/обрыве. Часть объяснения репорта «нет связи»:
   и клиент, и сервер маскируют причину.
   **Сделать:** `match next_field().await { Ok(Some(f))=>…, Ok(None)=>break,
   Err(e)=>return Err(…413/400 с причиной) }`.

3. **Удаление награды с заказами → 500, а в админке модалка висит.**
   `admin.rs` delete_reward: `DELETE FROM rewards` падает по FK
   `orders.reward_id` (NO ACTION) → `internal` 500. Плюс
   `Shop.tsx` `del()` у onOk нет `.catch` → Modal.confirm остаётся без
   ошибки и без результата.
   **Сделать:** на сервере отловить FK-ошибку → `conflict "есть заказы,
   деактивируйте"` (или мягкое удаление); в Shop.tsx добавить catch.

4. **Логины: регистр не нормализуется → дубли Ivan/ivan и невозможность
   войти.** `users.login UNIQUE` регистрозависим. Импорт проверяет дубли
   по `login = ANY($1)` (точное совпадение), сравнивает с lowercase —
   при наличии `Ivan` в БД файл с `ivan` проходит и создаёт второй аккаунт.
   `create_user` и вход тоже без trim/lowercase: логин с пробелом или другим
   регистром не входит, хотя rate-limit ключ их нормализует.
   **Сделать:** хранить логин в lower() (нормализовать при
   create/import/login), новой миграцией добавить уникальный индекс по
   `lower(login)` и сконвертить существующие.

5. **Нет верхней границы на минуты/дельты → 500 по переполнению и «тихие»
   огромные долги.** `teacher.rs` assign_hours: `minutes` любой i64 > 0 →
   `debt_minutes + minutes` переполняет BIGINT → 500. Опечатка «100 часов»
   вместо «10» создаёт реальный долг без подтверждения. То же в adjust_user
   (дельты) и в `RewardUpsertRequest` (price/stock): отрицательные значения
   валятся по CHECK → 500 вместо 400 (у create частично есть проверка,
   у update_reward её вообще нет — можно и пустое название).
   **Сделать:** bound-check `minutes <= ~100_000` и `price_minutes/stock >=
   0` до запроса, валидацию update такую же как create; в приложении —
   Alert-подтверждение суммы.

6. **Админ может сменить роль самому себе → мгновенный локаут.**
   `admin.rs` update_user: self-guard есть только у `is_active`, у `role`
   нет. Админ ставит себе role=student → теряет доступ при следующем же
   запросе (роль читается из БД). Если он единственный админ — восстановление
   только через SQL.
   **Сделать:** блокировать `req.role` при `id == auth.user.id`, либо
   требовать, чтобы оставался другой активный админ.

7. **`ensure_admin` не сработает, если все админы деактивированы.**
